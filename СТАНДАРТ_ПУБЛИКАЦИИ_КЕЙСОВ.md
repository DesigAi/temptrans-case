# Стандарт публикации кейсов

Этот файл — рабочий чек-лист для публикации кейсов. Он фиксирует подход, проверенный на кейсе TempTrans: один проект корректно читается и на компьютере, и на телефоне. С 2026-10-07 основная публикация TempTrans находится в отдельном проекте Vercel; GitHub Pages остаётся резервом.

## 1. Структура проекта

- TempTrans хранится в отдельном репозитории GitHub `DesigAi/temptrans-case`, подключённом к отдельному проекту Vercel `temptrans-case`.
- Для каждого языка создаётся отдельная папка и своя ссылка: например, `/ru/`, `/en/`, позднее — `/de/`.
- В корне лежат общие материалы: favicon и иконки для устройств.
- В языковой папке находятся PDF, обложка для предпросмотра ссылки, страница `index.html`, а также папки с изображениями и другими материалами версии.
- Этот документ обновляется только после появления проверенного правила, полезного для следующих кейсов.

## 2. Два режима просмотра

### Компьютер

- Основной формат — оригинальная PDF-презентация в браузере.
- Ссылка на языковую версию сразу открывает просмотр PDF.
- Десктопную презентацию не нужно переделывать в сайт: PDF сохраняет исходную логику слайдов и качество вёрстки.

### Телефон

- Основной формат — вертикальная мобильная версия: один вертикальный слайд за другим, читаемые обычной прокруткой страницы.
- Горизонтальную PDF-презентацию не использовать как основной способ чтения на телефоне: мелкий текст вынуждает пользователя масштабировать и двигать экран.
- PDF остаётся доступен отдельной заметной кнопкой «Открыть PDF»; он открывается в новой вкладке, где пользователь при необходимости сможет скачать файл.
- На телефоне PDF не должен загружаться в фоне. Это экономит трафик и ускоряет появление первого слайда.

## 3. Мобильные слайды

- Для каждого горизонтального слайда готовится отдельный вертикальный мобильный вариант. Смысл, дизайн и порядок сохраняются, но композиция адаптируется под вертикальный экран.
- Слайды идут строго по порядку: от первого до последнего. Пользователь читает их, прокручивая страницу вниз.
- Перед передачей в проект каждый PNG оптимизируется через TinyPNG или аналогичный сервис.
- Ориентир по весу одного слайда — около 500 КБ. Если текст и детали начинают заметно ухудшаться, приоритет у читаемости.
- Первый слайд загружается сразу. Все последующие получают ленивую загрузку и подгружаются при приближении пользователя к ним.
- У каждого изображения задаются фактические ширина и высота — так страница не «прыгает» при загрузке.
- Для всех слайдов используется асинхронное декодирование изображений.

## 4. Шапка мобильной версии

- Вверху страницы размещаются: короткий заголовок, кнопка «Открыть PDF», фото автора и краткое описание компетенций.
- Заголовок должен объяснять результат работы, а не быть нейтральным техническим названием вроде «Разбор кейса».
- В русском тексте не оставлять висячие короткие предлоги и союзы: использовать неразрывный пробел (`&nbsp;`).
- Кнопка PDF должна быть заметной, но не конкурировать по вниманию с заголовком.

## 5. Доверие и приватность

- Перед публикацией проверить все скриншоты на персональные данные.
- Личные номера сотрудников, директоров и другие чувствительные контакты в публичных материалах скрывать или размывать.
- Корпоративные публичные контакты можно оставлять, если они уже открыто размещены компанией и нужны для правдоподобности кейса.

## 6. Оформление ссылки

- У каждой языковой версии должны быть favicon и иконки для мобильных устройств.
- Настроить название, описание и OG-изображение, чтобы ссылка аккуратно выглядела в Telegram, WhatsApp, LinkedIn и других мессенджерах.
- Обложка ссылки должна быть понятна без открытия страницы: название кейса, компания и основной результат.

## 7. Проверка перед публикацией

- [ ] Компьютер: PDF открывается, листается и выглядит как исходная презентация.
- [ ] Телефон: страница быстро открывается, первый слайд читаем без увеличения и прокрутки в стороны.
- [ ] Телефон: PDF не загружается до нажатия кнопки «Открыть PDF».
- [ ] Телефон: все мобильные слайды идут по правильному порядку и без пропусков.
- [ ] Телефон: слайды ниже первого подгружаются при прокрутке.
- [ ] Ссылка: favicon, название, описание и обложка отображаются корректно.
- [ ] Приватность: личные номера и другие чувствительные данные в скриншотах скрыты.
- [ ] Проверены русская, английская и другие подготовленные языковые версии.

## 8. Как применять для нового кейса

1. Подготовить и проверить PDF для каждой языковой версии.
2. Опубликовать PDF-версию для компьютера.
3. Адаптировать слайды под вертикальный мобильный формат.
4. Оптимизировать изображения и разместить их в языковой папке проекта.
5. Настроить мобильную страницу, favicon и предпросмотр ссылки.
6. Пройти чек-лист из раздела 7 на компьютере и телефоне.
7. Опубликовать и проверить публичные ссылки.
